ShipBroker.
A freight quote in one screen.

This is an in-house prototype, built by Khatib Designs to show what a productised quoting tool actually looks like when you can operate it instead of reading about it. Pick a lane, a mode and an incoterm and it returns a price band, a transit estimate and the document list for that term. It runs entirely in your browser — nothing is sent anywhere, and there is no account to make. The figures are indicative model output, not a live carrier tariff.

The engine

Quote a shipment.

Six inputs. Every rate in the model is hard-coded in the page source, so you can read exactly how the number was reached.

Whatever this screen returns is illustrative model output from a rate table written into the page. It is not a carrier tariff and it is not a binding rate — a rate you can actually book against needs a live quote from the carrier or forwarder for the day you ship.

How this was built

The pattern, not the page.

The freight numbers are ours and made up. The structure underneath is the one we use when we turn a manual quoting job into a tool a company can hand to its customers.

The rate model is data, not code

Lanes, modes, cargo multipliers and incoterms are four plain objects at the top of one script. Repricing a lane is editing a number, not touching the calculation — which means the person who knows the rates can own them, and the change is one readable line in a diff. Swap those objects for a spreadsheet sync or an API and nothing else moves.

Incoterms drive the documents

The document list is not written per lane; it is derived from the term you picked, with the transport document swapped for the mode. That is the part people get wrong by hand, and it is the part worth encoding once: the rule lives in a single map that a trade compliance person can check without reading any logic.

Written to be bilingual

Every string a user sees is a label or a list item, not baked into the arithmetic, so an Arabic twin is a translation pass rather than a rebuild. We build Arabic-first for the GCC by default, and this demo is laid out so the same engine can serve both sides of the site.

It runs client-side, so it goes anywhere

No server, no build step, no request leaves the browser. That makes a tool like this cheap to embed in a marketing site, a customer portal or a WhatsApp landing page — and it means a prospect can use it before they ever speak to a salesperson.
